## 2. Proposed Solutions Breakdown

### Solution Candidate A: Overlap-Treatment Multi-Seed Noise Floor
- **Target Hypothesis**: Addresses `Hypothesis 1: Stochastic DDIM Sampling Noise Dominates Small Effect Sizes`
- **Component Affected**: Re-invocation of existing `experiments/step_segment/diff_gebd/iter_01/exp_002_val_overlap_context/run.py`'s `infer_and_export()` function, no new inference code — only new seed values against the already-fixed `--val-overlap-seconds 2.5` chunking.
- **Pros / Cons**:
  - *Pros*: Zero new code risk (reuses exactly the orchestration that already produced the 0.2975 single-sample result); directly resolves the explicitly-flagged missing probe from Hypothesis 1 with the cheapest possible follow-up (2 more inference passes, no retraining, no re-chunking of train data).
  - *Risks / Cons*: Still only yields a 3-sample noise band (same sample size as the baseline noise floor) — will narrow but not eliminate uncertainty about whether 0.2975 is a true population mean or a tail draw; if all 3 overlap-treatment seeds cluster tightly below the baseline noise floor, this experiment cannot on its own distinguish "genuinely worse due to merge interaction" (Hypothesis 2) from "genuinely worse due to a systematic overlap-context effect" — that separation is left to Solution Candidate B.

### Solution Candidate B: Pre-Merge vs. Post-Merge Boundary Candidate Diff
- **Target Hypothesis**: Addresses `Hypothesis 2: Overlap+Merge Interaction Nets Fewer Surviving Predictions`
- **Component Affected**: Read-only instrumentation around `tools/export_diffgebd_predictions.py::scores_to_preds_json` — no change to the shipped merge/suppression logic itself, only an additional debug-dump code path (e.g. `--dump-pre-merge <path>` flag, or a standalone analysis script reusing the same `boundaries_by_source` dict construction) so both pre- and post-merge candidate lists can be diffed for the same run.
- **Pros / Cons**:
  - *Pros*: Directly answers the diagnosis's missing probe ("is `merge_close_boundaries` discarding higher-confidence TP-adjacent candidates, or just legitimately collapsing duplicates?") with zero re-inference — reuses the already-saved `model_pred_dict_ep-1.pkl` from the existing `main_overlap_run` output directory. Cheapest and fastest of the three candidates (pure post-hoc analysis on existing artifacts).
  - *Risks / Cons*: A qualitative/example-based diff at a handful of chunk-seam locations (per the diagnosis's phrasing "at a handful of former-chunk-boundary timestamps") risks the same n=2-anecdote evidence-sufficiency critique the Debater raised against iter_01 — this experiment plan explicitly requires an **aggregate** count (how many total pre-merge candidates were collapsed/dropped dataset-wide, not just 2-3 example cases) to avoid repeating that mistake.

### Experiment 4 (NEW — Corrective Intervention): `exp_004_deterministic_noise_seeding`
- **Target Diagnoser Hypothesis**: Directly addresses `Hypothesis 1: Stochastic DDIM Sampling Noise Dominates Small Effect Sizes` (Confidence: 70%) — but unlike Experiments 1-3, this is a **fix**, not a measurement: it removes the noise source itself rather than characterizing its size.
- **Missing Probe Implemented / Human Directive**: Responds to the Debater's open question (`04_debate_verdict.md` §1.2) and Human's explicit instruction to add a corrective-intervention experiment rather than continuing pure diagnosis this iteration.
- **Variable to Isolate**: The **initial-noise RNG seeding strategy** in `src/step_segment/DiffGEBD/modeling/diffusion_model.py::ddim_sample()` — global-stream-order-dependent seeding (current behavior) vs. deterministic per-sample seeding (new). All other config/weights/thresholds held fixed.
- **Grounding (code-level finding, not assumption)**: `DIFFUSION.DDIM_SAMPLING_ETA: 0.0` (confirmed in `sewing_diffgebd_resnet50_chunk5s.yaml` and `modeling/config.py`) already makes every individual reverse-diffusion **step** deterministic — the `sigma * noise` term in `ddim_sample()` is always exactly zero since `sigma = eta * (...)  = 0`. The **only** remaining stochastic source in the entire sampling path is the single line `x_time = torch.randn(shape, device=self.device)` that draws each sample's **initial** noise tensor before the (otherwise fully deterministic) reverse-diffusion loop runs. Note: the originally-considered `DIFFUSION.DETERMINISTIC` config flag was investigated and found to **not** control this — it only toggles whether `train.py` validates once vs. loops over multiple `VALIDATION_TIMESTEPS` configs, and is not a valid lever for this hypothesis; this plan does not use it.
- **Baseline to Compare Against**: The existing baseline (overlap=0.0) 3-seed noise floor (0.3435-0.3790) and the `exp_001` overlap-treatment noise floor (once measured).
- **Implementation Changes**:
  - File: `src/step_segment/DiffGEBD/modeling/diffusion_model.py::ddim_sample()`. Replace the single global `torch.randn(shape, device=self.device)` initial-noise draw with a per-sample deterministic draw seeded from a stable, sample-identifying key (e.g. a hash of `video_id` + `chunk_index`, passed down from `validate()` in `train.py` through `forward()`/`ddim_sample()`), using a local `torch.Generator` rather than the global RNG stream — so each sample's initial noise no longer depends on how many other samples were drawn before it (and therefore no longer depends on `--val-overlap-seconds` chunk count).
  - This is a **single, isolated code change** confined to the noise-seeding mechanism — no change to model weights, thresholds, merge logic, or training.
- **Expected Outcome**:
  - Primary metric expectation: Re-running the SAME chunking config (e.g. overlap=0.0) twice with different global `--seed` values should now produce **identical or near-identical** Macro F1 (down to floating-point determinism limits), collapsing the previously-measured 0.0355 noise-floor spread to ~0. If true, this both **confirms** Hypothesis 1 (the spread was pure sampling-order artifact) and **fixes** it going forward, so future experiments' effect sizes can be measured against a near-zero noise floor instead of needing 3-seed repeats.
  - Verification test: Run the fixed sampling code twice (2 different global `--seed` values, e.g. 42 and 123) on the unmodified baseline (overlap=0.0) chunking; report whether Macro F1 is now identical/near-identical across the two runs. As a secondary check, re-run once on the overlap=2.5 config and confirm the per-sample noise draw is now independent of chunk count (i.e., the initial noise for a given `video_id`+`chunk_index` pair is bit-identical whether or not other chunks precede it in that run).
