# DDM-Net: Step Segmentation Tracker

> **Single Source of Truth** for method architecture, issue tracking, and experiment metrics for **DDM-Net** on industrial sewing step segmentation.

---

## 1. Method Info

### 1.1. Overview & Architecture
- **Framework**: [DDM-Net](https://github.com/MCG-NJU/DDM) (*Dense-to-Discrete Motion Network for Generic Event Boundary Detection*), vendored from [NVIDIA SOP Monitoring Blueprints](https://github.com/NVIDIA/sop-monitoring-blueprints).
- **Core Mechanism**:
  - Deterministic per-frame binary classifier for generic event boundaries.
  - Dual-stream representation: RGB spatial branch + Dense Difference Module (DDM) motion branch.
  - 6-layer **Co-Transformer Decoder** models cross-modal spatio-temporal interactions and feeds multi-layer prediction heads.
- **Repository Implementation**: `src/step_segment/DDM-Net/`
  - Engine: PyTorch Lightning 2.x (`train_sop_lightning.py`, `pl_ddm_datamodule.py`).
  - Dataloaders: `ddm_dataset.py` (sparse PyAV random sampling for train) and `ddm_val_dataset.py` (dense `decord` streaming for val).
  - Backbones: ResNet-50 and DINOv2 (`dinov2_vitb14` / `dinov2_vits14`).
  - Configuration: `config/ddm_train_config.yaml`.

### 1.2. Ground Truth Event Definition
In `action_segments_annotated.json`, consecutive micro-actions sharing the same `operation_name` are merged into **step segments** via `tools/process_step_segments.py`. Empty (`""`) and `"UNKNOWN"` intervals are preserved as distinct transition segments. Ground-truth boundaries occur where the macro operation changes.

### 1.5. Key Hyperparameters
- `dataset_config.frames_per_side`: Temporal half-window (default 5 $\to$ recommend 8).
- `dataset_config.downsample`: Frame subsampling step (default 1 $\to$ recommend 2).
- `training_config.aux_loss_weight`: Weight for intermediate decoder auxiliary heads (set to 0.3).
- `training_config.model_ema`: Exponential moving average on model weights for inference stability.

## 2. Status & Issues

### 2.1. Status Matrix

| Issue | Severity | Status | Solution Summary |
|---|---|---|---|
| **18-Head Unweighted Loss Plateau** | 🔴 CRITICAL | In Progress | Loss stalls at ~12.47 ($18 \times \ln(2)$) from random guess across 18 heads; weight main head `main + 0.3 * aux` |
| **Validation System RAM Leak (OOM)** | 🔴 CRITICAL | Solved | `decord` native C++ buffer leak + multiprocessing multiplication; set `workers: 1`, periodic reader release |
| **Narrow Temporal Window (0.37s)** | 🟡 HIGH | Planned | 11 frames cover only ~18% of 1.84s median action; switch to `downsample: 2, frames_per_side: 8` (1.10s) |
| **Small ROI & Background Noise** | 🟡 MEDIUM | Planned | 70% background in 1080p frame; auto-crop bounding box from `*.mask.png` before 224x224 resize |
| **Frozen DINOv2 Backbone** | 🟡 MEDIUM | Evaluating | Zero sewing domain adaptation; unfreeze final 2 transformer blocks with lower LR ($10\times$ smaller) |
| **Premature LR Decay** | 🟢 MINOR | In Progress | Cosine scheduler drops to `1e-10` too early; add 3 warmup epochs, raise `min_lr: 1e-6` |

### 2.2. Root Cause Analyses

#### A. 18 Unweighted CrossEntropy Heads Stalling Loss at ~12.47
- **Root Cause**: The 6-layer Co-Transformer outputs intermediate predictions across 3 branches (`outputs`, `rgbs`, `ddms`), totaling $6 \times 3 = 18$ `CrossEntropyLoss` heads summed uniformly:
  $$\text{Loss} = \sum_{i=1}^6 L_{\text{comb}}^{(i)} + \sum_{i=1}^6 L_{\text{rgb}}^{(i)} + \sum_{i=1}^6 L_{\text{ddm}}^{(i)}$$
  For random binary predictions, $-\ln(0.5) \approx 0.693$. Summed over 18 heads: $18 \times 0.693 \approx 12.47$, matching observed flat loss. Gradients from shallow auxiliary heads corrupt the main head (`outputs[-1]`).
- **Fix**: Re-weight loss to prioritize the final prediction:
  $$\text{Loss} = L_{\text{main}} + 0.3 \times \frac{1}{N_{\text{aux}}} \sum L_{\text{aux}}$$

#### B. Validation RAM OOM Killer
- **Root Cause**:
  1. `decord.VideoReader` maintains an internal uncompressed C++ frame buffer that accumulates during dense streaming (`temporal_stride=1`).
  2. PyTorch DataLoader `num_workers > 0` forks separate processes, multiplying native memory overhead.
  3. `self.validation_step_outputs` retained 700+ step outputs in RAM until epoch end.
- **Fix**: Set `val_config.workers: 1`, enforce periodic reader recreation (`chunk_duration: 60.0s`), and clear intermediate buffers.

#### C. Temporal Receptive Field Mismatch
- **Data Reality**: Dataset statistics over 1,570 actions:
  - Median duration: **1.84s** (~55 frames @ 30 FPS). Mean duration: **2.90s** (~87 frames).
  - Actions < 2s: **54.0%** (Train) / **64.5%** (Val).
- **Bottleneck**: Baseline `frames_per_side: 5, downsample: 1` yields:
  $$\text{Span} = 2 \times 5 + 1 = 11\text{ frames} \approx 0.37\text{s}$$
  Covering only 15–20% of an operation, missing boundary context entirely.
- **Solution**: Set `downsample: 2, frames_per_side: 8`:
  $$\text{Span} = (2 \times 8) \times 2 + 1 = 33\text{ frames} \approx 1.10\text{s}$$
  Expands coverage to 1.10s (spanning end of previous and start of next action) while adding only 6 frames to input tensor (17 vs 11).

## 3. Experiments & Results

### 3.1. Training Trajectory (DINOv2 ViT-B/14 Baseline, Epochs 0–6)
- **Setup**: `dinov2_vitb14`, `freeze_backbone: true`, batch size 4, 1x RTX 5060 16GB.

| Epoch | Train Loss | Val F1-Score | Val Accuracy | Notes |
|:---:|:---:|:---:|:---:|:---|
| **0** | 12.48 | **0.4530** | 24.2% | Flat loss initialization |
| **1** | 12.35 | 0.3955 | 31.9% | F1 drop |
| **2** | 12.28 | **0.4546** | 19.7% | Peak checkpoint (Top 1) |
| **3** | 12.21 | 0.4342 | 47.8% | High accuracy variance |
| **4** | 12.24 | 0.4011 | 19.6% | Performance regression |
| **5** | 12.20 | 0.3987 | 21.3% | Performance regression |
| **6** | 12.22 | 0.4105 | 22.0% | Complete loss stagnation |

- **Diagnosis**: Severe underfitting caused by auxiliary loss dilution and premature LR decay. Dataset scale (25 train videos, 1,190 boundaries, 904 steps/epoch) is sufficient and not the root cause.

### 3.2. Hardware Benchmarks
- **Training throughput**: ~59 min/epoch (~0.25 it/s).
- **GPU VRAM**: ~8.5GB / 16GB.
- **RAM usage**: Stable at ~3.5GB during train; spiked to 16GB during baseline val (fixed to ~4GB with single worker).

### 3.3. Next Actions
1. Re-train with `aux_loss_weight: 0.3`, 3 warmup epochs, `min_lr: 1e-6`, base LR `2.5e-4`.
2. Expand window to `downsample: 2, frames_per_side: 8`.
3. Integrate `mask.png` bounding box crop.
